# ADR 0005: Existing-account email-link sign-in

Status: email-link path implemented but unverified; owner password sign-in and session persistence verified in ad-hoc-signed Simulator.

The owner prefers signing in by clicking an email link rather than entering a password in Simulator. Keep the existing email/password path, and add Supabase `signInWithOTP` using the already allowlisted `healthtracker://auth-callback` redirect with `shouldCreateUser = false`. This cannot silently create another account. The callback exchanges the code through the same Supabase client that requested the link, retaining its PKCE verifier. The link must therefore be opened on the same Simulator or physical iPhone that requested it, not merely on the Mac browser. Never log or commit the link, code, session token, or password.

The first Simulator-requested link was consumed by a Safari login on another iPhone according to Auth audit logs. A later Simulator-requested link returned invalid/expired in the app, but the audit log does not establish whether a scanner, browser handling, or another cause consumed it. A further request hit the project's email rate limit. Do not treat those attempts as a successful Simulator sign-in. Retry only with a fresh link opened on the requesting Simulator promptly, or use the account password directly in the app; do not copy a device session into the repository.

The unsigned Simulator build showed “Signed in” immediately after password login but lost the session on app restart; its Data API requests returned `permission denied for table meals`/`health_samples`. Direct password authentication plus REST SELECT with the same account returned HTTP 200 for both tables, and live SQL verified their authenticated SELECT grants and RLS policies. Rebuilding with Xcode's default ad-hoc signature, without changing Auth code or database permissions, made meal and Health cloud sync succeed and retained the session across a full app close/reopen. The evidence points to session storage failing for the unsigned build; the exact Keychain error was not captured. Keep Simulator cloud QA signed, and do not weaken RLS to compensate for an absent session.
